# PRメッセージを作成する

`.github/pull_request_template.md` を読み、見出しと順序を維持してPR本文を作成する。

## 手順

1. PRの目的、意図的に対象外としたこと、実施済みの確認を把握する。情報がなければ推測で補わない。
2. 各セクションがPRの理解に必要かを判断する。不要または根拠のないセクションは、見出しだけを残して空欄にする。
3. 完成したPR本文だけを日本語で出力する。

## 各セクション

- **タスク番号**: 判明しているチケット番号または課題番号だけを記載する。
- **変更点**: ユーザーが得る変化、解決する課題、達成した価値を記載する。通常は1〜3項目にする。
- **やっていないこと**: 意図して今回の範囲から外した、レビュー判断に影響する事項だけを記載する。
- **確認したこと**: 実際に実施したテスト、確認した振る舞い、確認結果だけを記載する。
- **その他**: 依存関係、展開時の注意、確認してほしい判断など、他のセクションに入らない重要事項だけを記載する。

## 書き方

- 主体はユーザーにする。必要な場合は「ユーザーは〜できる」と書き、「私」は使わない。
- 明朗かつ簡潔に、1項目につき1文を基本にする。
- あいまいな表現を避ける。「改善した」「対応した」だけで終えず、何がどう変わるかを明記する。
- 修正ファイルの列挙、コンポーネント名、関数名、差分の逐次説明など、コードレベルの詳細を書かない。
- 根拠がない効果、未確認の結果、将来の予定を書かない。
- 伝える価値がない説明は加えない。簡潔さを優先する。

## 出力形式

```markdown
## タスク番号

## 変更点

- ユーザーは〜できる。

## やっていないこと

## 確認したこと

## その他
```
